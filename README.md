### Подход к разработке

Придерживаюсь единой архитектуры во всех проектах — это упрощает сопровождение и передачу кода другому разработчику:

- Разделение слоёв: **Route → Controller → Service → Repository**. Контроллеры тонкие, бизнес-логика в сервисах, работа с БД изолирована в репозиториях.
- Валидация вынесена в Form Requests, формат ответов API — в Resource-классы.
- Тесты на ключевые сценарии: feature-тесты на бизнес-процессы, unit-тесты на сервисный слой.
- Тяжёлые операции — в очередях, а не в HTTP-запросе.
- В зависимостях и Docker-образах использую стабильные проверенные версии, а не последние релизы.
